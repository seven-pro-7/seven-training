# GZCLP 8 周训练追踪 · 微信小程序

由《SEVEN_GZCLP_扩展容量版_8周全自动追踪表.xlsx》转化而来。规则引擎已用 4 个训练日 × 8 周、随机填入的数据与 Excel 公式真实计算结果逐格比对（D/E/G/H/I 共 800 格），**0 差异**。

## 运行
1. 微信开发者工具 → 导入项目 → 选择本目录（`project.config.json` 中 appid 为 `touristappid`，正式发布前请换成自己的 AppID）
2. 首次启动会自动写入 Excel 默认参数，以及已填写的第 1 周 A1 / B1 记录
3. 网页版：`python3 preview/build.py` 会同时生成 `preview/index.html`（本地预览）和 `../gzclp-web/`（发布目录，含主屏幕图标）。数据存在浏览器 localStorage，格式和小程序一致，可以通过导出/导入 JSON 迁移

## 目录
```

utils/chart.js    Canvas2D 图表：折线 / 堆叠柱 / 环形
utils/store.js    wx.setStorageSync 本地存储
pages/train       训练：推荐训练日、实时判定、组进度点、休息计时、结算
pages/plan        计划：8 周 × 4 日矩阵、当前状态总览
pages/stats       数据：KPI、e1RM 回归、重量走势、容量、判定分布、PR、体重
pages/review      回顾：教练小结、周报、训练日志（可改可删）
pages/settings    设置：1RM/TM、步幅、阈值、规则模式、减载、动作替换、导入导出
```

## Excel → 小程序 对应关系
| Excel | 公式 / 逻辑 | 小程序 |

| 参数设置 C12:C18 | 步幅 / T3 阈值 25 | 设置 · 进阶步幅 |
| 各训练日 E 列首周 | `ROUND(TM×系数/2.5,0)*2.5`（系数 85% / 70% / 65% / 55% / 50%，或固定值） | 设置 · 训练日动作 |

## 分析时发现的表格问题（已在小程序中处理）
1. **T1 公式只覆盖 5×3+**：H 列写死为 `IF(F>=3,"5×3+","6×2+")`，进入 6×2+ 后只要 AMRAP≥3 就会跳回 5×3+，也不判断“连续 2 次”，10×1+ 阶段根本不会出现。默认的“完整三阶规则”模式按备查表完整实现；切到“严格按表格公式”则逐格还原 Excel。
2. **T2 3×8 完成后规则不一致**：备查表写“重量不变，继续 3×8”，公式是“加重并回到 3×10”。目前以公式为准，规则速查里也做了标注。
3. **T3 上肢 1.25kg 步幅实际等于 2.5kg**：`ROUND((50+1.25)/2.5)*2.5 = 52.5`（四舍五入），按档位取整后 1.25 永远会进位到 2.5。已保留原逻辑，可以在设置里把取整档位改成 1.25。
4. **减载周没有公式**：备查表写了每 6 周减载一次，表格里没有实现。小程序第 6 周自动提示，T1 -50%、T2 -40%、T3 少 1 组，减载不改变进阶链。
5. 参数总览里俯卧腿弯举 10、俯身划船 45 是手填数，不会随训练更新；小程序中全部改为自动计算。

## 新增能力
- **周期动作自动轮换（每 8 周一轮）**：
  - T1 四大项永不轮换；T2/T3 的 16 个位置在每轮开始时自动换成新动作，**一轮内保持不变**，不与上一轮重复，同一轮内每个动作只出现一次，候选里优先选最久没练过的。
  - 每个位置有固定「角色」（深蹲变式、髋铰链、垂直拉、肱三头……），只在同一动作模式的候选池里轮换，每周推/拉/蹲/髋铰链比例与训练量不变。
  - 换入的新动作重新进阶（T2 从 3×10、T3 从 3×15+），起始重量 = max(按当前估算 1RM 推算, 该动作上次重量 × 90%)；估算 1RM 取 T1 末组 AMRAP 的 Epley 值 × 90%，只在高于设置里的 1RM 时采用。
  - 计划页新增「第 N 轮动作编排」卡片，可用 ‹ › 预览未来任意一轮，并展开「编排依据」；设置页可关闭自动轮换、或锁定某个位置；轮内用「以后都用」手动换的动作只管到本轮结束。
  - 依据：Kassiano 等 2022 系统综述（JSCR 36:1753，有计划的变化有益、随意高频轮换有害、刺激重复的轮换无效）；Fonseca 2014（JSCR 28:3085，轮换动作组股四头肌四个头均增长且深蹲 1RM 提升最大）；Maeo 2021（MSSE，坐姿腿弯举优于俯卧）；Maeo 2023（EJSS，过头臂屈伸优于下压）。
- **动作库 v2（器械感知推荐重量）**：
  - T1 严格只保留四大项：杠铃深蹲、平板卧推、传统硬拉、站姿实力推；搜索、更换和自定义入口都不能把其他动作加入 T1。
  - 所有动作统一标记为「杠铃 / 哑铃 / 自重 / 负重 / 器械」之一；哑铃重量表示**单只**，负重表示**外加重量**（不含体重），自重只记录次数，器械表示配重片。
  - 推荐模型：T1 首周 = 四大项 1RM × 76.5%（即 TM 90% × 85%）；T2 = 基准主项 1RM × 动作间强度系数 × 65%；T3 = 基准主项 1RM × 动作间强度系数 × 50%。更换动作优先沿用该动作上次实际重量，无历史才用模型。设置页显示推导式并可「采用」，不会未经确认改写已有训练链。
  - 器械档位：杠铃 2.5kg（上肢 +2.5 / 下肢 +5）、哑铃单只 1~2kg、负重外加 1.25~2.5kg、固定器械 2.5~5kg；T3 只跨一个最小档位。自重达到 25 次改为「建议负重」，不会把 0kg 错算成加重。
  - 参考：NSCA %1RM 次数关系（10RM≈75%、15RM≈65%）；GZCLP T1/T2/T3 强度区间与四大项结构（https://thefitness.wiki/routines/gzclp/）；动作间强度比例参考 Strength Level、Hypro 与 Symmetric Strength 的同级数据。器械品牌、动作幅度和训练经验会造成偏差，所以模型只给保守起点，实际训练表现优先。
- **动作库刷新（T2/T3）**：四天的 T2/T3 动作重排，全程每个动作唯一、不再跨天重复（原先坐姿哑铃推肩/高位下拉/俯身划船各出现两次，会以两套独立重量各自每周加重，造成理解和误操作成本）。加重规则本身不变——每个动作在四天轮转里每轮（每周）出现一次，练到就推进，所以表现为"每周加重"，符合 GZCLP。已有记录按槽位 ID 存储，不受动作名变化影响；升级会自动把未手动更换过的槽位刷新为新动作，已手动更换的保留。
  - A1 下肢蹲：前蹲 / 上斜卧推 · 高位下拉 / 俯卧腿弯举
  - B1 垂直推：坐姿哑铃推肩 / 罗马尼亚硬拉 · 引体向上 / 哑铃侧平举
  - A2 水平推：窄距卧推 / 杠铃深蹲 · 杠铃弯举 / 绳索三头屈伸
  - B2 水平拉：潘德雷划船 / 坐姿划船 · 面拉 / 哑铃弯举
- **底部按钮安全区**：网页弹层不再延伸到底部 Tab 下方；确认按钮固定在弹层可视区内，与 Tab 保持 28px 以上间距。小程序弹层按钮增加安全区和 sticky 保护，长内容滚动时也能点击。
- **多轮 8 周循环**：完成一轮（8 周 × 4 日）后自动进入下一轮，可无限循环。训练页与结算显示"第 N 轮 · 第 M 周"；计划页矩阵按轮显示并可用 ‹ › 切换查看任意一轮（含向后预览一轮），顶部"本轮进度"始终锁定当前进行中的那一轮，另显示累计次数；减载改为按每轮内的周序计算（默认每轮第 6 周）。每轮周数在设置页可调。
- **按周整体推进**：当前周 = 四个训练日中完成次数最少者 + 1。本周 A1、B1、A2、B2 都完成后，才会整体切换到下一周；本周已完成的训练日会显示「已完成」，只能查看或修改，不能提前开练下一周。顶部显示本周进度（如 2/4）和剩余训练日，完成第 4 次时结算页会提示「第 N 周完成」。
- **手动调整重量**：训练卡上点重量数字 →「调整」，可以用 ± 按取整档位增减，也可以直接输入。本次判定和容量按实际重量计算，下次重量在实际重量的基础上推进；卡片会显示建议重量，可一键恢复。日志和详情里会标注「手动」。减载周手动改重量不影响后续加重链。
- 容量 = 重量 × 组 × 次（T1/T3 末组用 AMRAP 实际次数；T2 未完成时可以填实际总次数）
- e1RM（Epley：重量 × (1 + AMRAP/30)）+ 最小二乘线性回归：斜率（kg/周）、R²、第 8 周预测
- 教练小结：连续加重、降阶预警、T3 接近阈值、回归趋势、减载提醒；可以一键复制
- 修改或删除任意一次历史记录后，之后的阶段和重量全部自动重算
